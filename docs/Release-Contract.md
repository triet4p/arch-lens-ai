# Release Contract

This document defines the version and release contract for Arch Lens AI.

## Version Source of Truth

There is no hidden implicit source of truth. Releases are created by explicitly choosing a semantic version and then synchronizing all required manifests with:

```powershell
pwsh scripts/bump-version.ps1 -Version 0.2.0
```

The bump script must leave these files synchronized:

- `package.json`
- `frontend/package.json`
- `src-tauri/tauri.conf.json`
- `package-lock.json`
- `frontend/package-lock.json`
- `src-tauri/Cargo.toml`
- `python-sidecar/pyproject.toml`

The sync can be verified independently with:

```powershell
pwsh scripts/check-version-sync.ps1
```

## Tag Naming

Git tags for releases must use:

```text
vX.Y.Z
```

Example:

```text
v0.2.0
```

The tag version must match the synchronized manifest version exactly, without additional suffixes.

## Release Title

GitHub Releases use:

```text
Arch Lens AI vX.Y.Z
```

## Installer Asset

The primary Windows release artifact is the NSIS setup executable generated by Tauri.

Expected bundle path pattern:

```text
src-tauri/target/release/bundle/nsis/*-setup.exe
```

Expected naming pattern:

```text
Arch Lens AI_X.Y.Z_x64-setup.exe
```

If Tauri changes the precise filename, the release workflow still uploads the generated `*-setup.exe` file from the NSIS bundle directory, but the contract remains that exactly one setup executable is published per tag.

## Release Sequence

1. Synchronize manifests with `scripts/bump-version.ps1`.
2. Commit the version change.
3. Create tag `vX.Y.Z`.
4. Push the commit and tag.
5. GitHub Actions validates version sync, builds the sidecar, builds the Tauri installer, and publishes the matching setup `.exe`.

For Windows release builds, the verified stable path uses `CARGO_BUILD_JOBS=1` during `tauri build` to avoid intermittent memory failures while compiling the Tauri dependency stack.

## Non-Goals

- `src-tauri/Cargo.lock` is not treated as a version source of truth.
- The release contract currently targets the Windows setup installer only.
- Code signing is not part of the current contract yet.
